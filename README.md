## Описание системы

ПОЗИЦИИ-АСУБАНК — один из трёх компонентов банковской АС:

| Компонент | Команда | Назначение |
|---|---|---|
| FX-АСУБАНК | №1 | Создание и верификация валютных сделок |
| **ПОЗИЦИИ-АСУБАНК** | **№2** | **Мониторинг и корректировка позиций по счетам ностро** |
| ОТЧЕТЫ-АСУБАНК | №3 | Регламентированная отчётность и НСИ |

### Что делает система

- **Формирует позицию** по каждому счёту ностро при поступлении платежа из FX-АСУБАНК
- **Рассчитывает текущий остаток** по формуле:
  ```
  Текущая позиция = Входящий остаток + Корректировки + Оборот IN − Оборот OUT
  ```
- **Уведомляет** систему FX-АСУБАНК при превышении лимита по счёту
- **Позволяет позиционеру** корректировать входящие остатки (сверка с банковскими выписками)
- **Ведёт журнал аудита** всех действий пользователей
- **Предоставляет данные** системе ОТЧЕТЫ-АСУБАНК для формирования регламентированной отчётности

## Установка и запуск

### Требования

- Python 3.10 или выше
- Доступ к интернету (для SSH-подключения к серверу БД)

### Шаг 1 — Клонировать репозиторий

```bash
git clone <url-репозитория>
cd POSITIONS-ASUBAN
```

### Шаг 2 — Создать виртуальное окружение

```bash
python3 -m venv venv
source venv/bin/activate        # Linux / macOS
# или
venv\Scripts\activate           # Windows
```

### Шаг 3 — Установить зависимости

```bash
pip install -r requirements.txt
```

> **Важно:** Если установка `psycopg2-binary` завершается ошибкой, установите его отдельно:
> ```bash
> pip install psycopg2-binary
> ```

### Шаг 4 — Заполнить базу данных начальными данными

Запускается **один раз**. Скрипт создаёт таблицы и добавляет тестовые данные.

```bash
python3 seed.py
```

Ожидаемый вывод:
```
✓ Валюты добавлены
✓ Счета ностро добавлены
✓ Входящие остатки на сегодня добавлены
✓ Пользователи добавлены

=== Готово! Начальные данные загружены. ===

Учётные данные для входа:
  Администратор: admin / Admin@123
  Позиционер:    positioner01 / Pos@123
  Трейдер:       trader01 / Trader@123
```

### Шаг 5 — Запустить бэкенд

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Бэкенд запустится на `http://localhost:8000`.

| URL | Описание |
|---|---|
| `http://localhost:8000/docs` | Интерактивная документация Swagger UI |
| `http://localhost:8000/redoc` | Документация ReDoc |
| `http://localhost:8000/health` | Проверка работоспособности |

### Шаг 6 — Запустить фронтенд (в отдельном терминале)

```bash
cd frontend
npm install
npm run dev
```

Фронтенд откроется на `http://localhost:3000`.

> Бэкенд должен быть запущен до открытия фронтенда — иначе API-запросы вернут ошибку сети.

## API — полный справочник

Полная интерактивная документация доступна по адресу `http://localhost:8000/docs` после запуска сервера.

### Авторизация

Все эндпоинты (кроме `/auth/login` и `/payments/incoming`) требуют JWT-токен в заголовке:
```
Authorization: Bearer <токен>
```

#### POST `/auth/login` — Вход в систему

```json
// Запрос
{
  "логин": "admin",
  "пароль": "Admin@123"
}

// Ответ 200
{
  "access_token": "eyJ...",
  "token_type": "bearer",
  "пользователь": {
    "id": "...",
    "логин": "admin",
    "роль": "ADMIN",
    "активен": true
  }
}
```

#### POST `/auth/logout` — Выход

Требует токен. Фиксирует выход в журнал аудита.

#### GET `/auth/me` — Текущий пользователь

Возвращает данные авторизованного пользователя.

### Мониторинг позиций

#### GET `/positions/` — Позиции по всем счетам

Параметры запроса:
- `дата` — дата (по умолчанию — сегодня, формат `YYYY-MM-DD`)
- `код_валюты` — фильтр по валюте (например, `USD`)

```json
// Ответ 200
[
  {
    "id_счета": "575e7efe-...",
    "номер_счета": "30111840000000001001",
    "наименование_счета": "Ностро USD в Citibank",
    "код_валюты": "USD",
    "дата": "2026-05-25",
    "входящий_остаток": "1200000.00",
    "сумма_корректировок": "50000.00",
    "оборот_in": "250000.00",
    "оборот_out": "0",
    "текущая_позиция": "1500000.00",
    "лимит": "500000.00",
    "превышение_лимита": false
  }
]
```

#### GET `/positions/{account_id}` — Позиция по конкретному счёту

Параметры: `дата` (опционально).

#### GET `/positions/opening-balances/` — Входящие остатки

Параметры: `дата`, `id_счета` (опциональны).

#### POST `/positions/opening-balances/` — Установить входящий остаток

Доступно: **Позиционер, Администратор**

```json
// Запрос
{
  "id_счета": "575e7efe-...",
  "дата": "2026-05-26",
  "сумма": 1500000.00
}
```

## Тестирование

### Вариант 1: Swagger UI (рекомендуется)

1. Откройте `http://localhost:8000/docs`
2. Нажмите **Authorize** (кнопка в правом верхнем углу)
3. Войдите через `POST /auth/login` — скопируйте `access_token`
4. Вставьте токен в поле `HTTPBearer (http, Bearer)` → **Authorize**
5. Теперь все эндпоинты доступны с авторизацией

### Вариант 2: Python-скрипт

Создайте файл `test_api.py` и запустите его:

```python
import requests

BASE = "http://localhost:8000"

# --- 1. Авторизация ---
r = requests.post(f"{BASE}/auth/login",
                  json={"логин": "admin", "пароль": "Admin@123"})
token = r.json()["access_token"]
headers = {"Authorization": f"Bearer {token}"}
print("Авторизация: OK")

# --- 2. Получить позиции ---
r = requests.get(f"{BASE}/positions/", headers=headers)
positions = r.json()
print(f"Позиции по {len(positions)} счетам:")
for p in positions:
    print(f"  {p['номер_счета']} ({p['код_валюты']}): {p['текущая_позиция']}")

# --- 3. Принять платёж от FX ---
account_id = positions[0]["id_счета"]
r = requests.post(f"{BASE}/payments/incoming", json={
    "id_сделки": "11111111-1111-1111-1111-111111111111",
    "код_валюты": positions[0]["код_валюты"],
    "сумма": 100000.00,
    "дата_валютирования": "2026-05-25",
    "id_счета": account_id,
    "направление": "IN"
})
result = r.json()
print(f"\nПлатёж принят: позиция = {result['текущая_позиция']}, превышение лимита = {result['превышение_лимита']}")

# --- 4. Авторизоваться как позиционер и скорректировать остаток ---
r = requests.post(f"{BASE}/auth/login",
                  json={"логин": "positioner01", "пароль": "Pos@123"})
p_headers = {"Authorization": f"Bearer {r.json()['access_token']}"}

r = requests.get(f"{BASE}/positions/opening-balances/",
                 params={"id_счета": account_id}, headers=p_headers)
ob_id = r.json()[0]["id"]

r = requests.post(f"{BASE}/corrections/", headers=p_headers, json={
    "id_входящего_остатка": ob_id,
    "сумма": 25000.00,
    "комментарий": "Тестовая корректировка"
})
print(f"\nКорректировка создана: {r.json()['сумма']}")

# --- 5. Проверить, что трейдер не может корректировать ---
r = requests.post(f"{BASE}/auth/login",
                  json={"логин": "trader01", "пароль": "Trader@123"})
t_headers = {"Authorization": f"Bearer {r.json()['access_token']}"}
r = requests.post(f"{BASE}/corrections/", headers=t_headers,
                  json={"id_входящего_остатка": ob_id, "сумма": 1000.00})
print(f"\nТрейдер пытается скорректировать: {r.status_code} (ожидается 403)")

# --- 6. Проверить журнал аудита ---
r = requests.get(f"{BASE}/admin/audit", headers=headers)
audit = r.json()
print(f"\nЗаписей в журнале аудита: {len(audit)}")
for entry in audit[:5]:
```

## Интеграция со смежными системами

### FX-АСУБАНК → ПОЗИЦИИ-АСУБАНК (входящий поток)

При подтверждении сделки FX-АСУБАНК вызывает:

```
POST /payments/incoming
```

Система принимает платёж, пересчитывает позицию и при необходимости возвращает флаг `"превышение_лимита": true`.

### ПОЗИЦИИ-АСУБАНК → ОТЧЕТЫ-АСУБАНК (исходящий поток)

Система ОТЧЕТЫ-АСУБАНК запрашивает данные через:

```
GET /integration/reports/positions?дата=2026-05-25
```

Возвращает агрегированные позиции по всем активным счетам на указанную дату.

Интеграция работает через реальные HTTP-контракты внутри общего compose-стека:
FX-АСУБАНК отправляет платежи в `POST /payments/incoming`, а ОТЧЕТЫ-АСУБАНК
читает позиции через `GET /integration/reports/positions`.

### Как работает авторизация на фронтенде

1. При входе (`POST /auth/login`) фронтенд получает `access_token` и объект пользователя
2. Токен и данные пользователя сохраняются в `localStorage`
3. Все последующие запросы автоматически включают заголовок `Authorization: Bearer <token>` (через Axios interceptor)
4. При получении ответа `401` фронтенд автоматически очищает localStorage и перенаправляет на `/login`

### Разграничение прав на фронтенде

Фронтенд читает роль из объекта пользователя (`user.роль`) и:
- Скрывает кнопки "Создать счёт", "Добавить валюту" для не-ADMIN
- Скрывает кнопку "Новая корректировка" для TRADER
- Скрывает пункты меню "Пользователи" и "Журнал аудита" для не-ADMIN
- Защищённые маршруты перенаправляют на `/login` при отсутствии токена

### Особенности работы с API

API бэкенда использует кириллические имена полей в JSON-запросах и ответах (в соответствии с ТЗ). Фронтенд использует эти же имена при формировании запросов. Например:

```js
// POST /auth/login
{ "логин": "admin", "пароль": "Admin@123" }

// POST /corrections/
{ "id_входящего_остатка": "uuid...", "сумма": 50000, "комментарий": "Причина" }
```
